# Локальное подключение авторизации

- POST /api/auth/login отправляет email/password, затем GET /api/auth/me проверяет токен. Только после успешного профиля сохраняется сессия и открываются внутренние страницы.
- POST /api/auth/register подготовлен с email/password/confirmPassword/personalDataConsent. До approved=true у согласованного документа запрос заблокирован, в том числе в DEV. Не утверждать черновик автоматически.
- После успешной регистрации показывается «Аккаунт создан», но пользователь не считается вошедшим. Письмо не отправляется текущим backend, экран успеха это поясняет.
- Пароли не записываются в хранилище, URL или логи. Токен хранится в sessionStorage под существующим ключом; демо-флаг удаляется при реальном входе.
- Ошибки, таймаут и повторные нажатия обрабатываются. Неизвестные серверные подробности не отображаются пользователю.
- Vite проксирует /api в локальный backend:8080 без удаления префикса; настройка пользователя сохранена.
- nginx проксирует /api/ в сервис backend:8080 общей Docker-сети. Для применения нужно пересобрать frontend. Не пересобирать backend из feature/dashboard: эта ветка пока не содержит новых backend-коммитов master.
- Dashboard API по-прежнему отсутствует. При настоящем входе демо-данные не подменяют реальные.

Этот документ уточняет прежний статус в REGISTRATION.md: код API теперь подготовлен, но блокировка черновика согласия остаётся; подтверждение почты backend ещё не реализовал.

Проверка: npm run build, npm test. API-тесты используют подставные ответы и не создают пользователей. Реальный успешный вход нужно дополнительно проверить с тестовым аккаунтом команды.
