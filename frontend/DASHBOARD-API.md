# Dashboard: интеграция API

Контракт сверён с контроллером, DTO и `/v3/api-docs` работающего backend.

- `GET /api/dashboard/summary?month=YYYY-MM`: месячный эквивалент и календарные списания, отдельно по валютам.
- `GET /api/dashboard/categories?month=YYYY-MM`: категории и суммы. Группировку «Другое» выполняет сервер, используется его стандартный порог; клиент не группирует повторно.
- `GET /api/dashboard/upcoming`: полный список без limit и итоги по валютам. Dashboard показывает первые четыре будущих платежа; попап получает весь список выбранной валюты.

Все запросы используют Bearer-сессию и общий клиент с таймаутом. 401 завершает сессию; 403/ошибки сервера и некорректные ответы дают понятное сообщение и повторную загрузку. Смена месяца, валюты, пользователя и уход со страницы отменяют запросы; устаревшие ответы не отображаются. Демо доступно отдельно только в DEV и не используется после ошибок реального API.

Карточки, диаграмма и попапы используют один набор данных. Месяц сводки меняется на странице; история категорий загружается также из селекта попапа. При загрузке истории старые суммы скрываются, ошибка допускает повтор. Поддержаны RUB/USD/EUR/CNY с явным выбором: конвертации и сложения разных валют нет.

Адаптер проверяет месяц ответа, денежную точность, безопасные целые копейки, уникальные идентификаторы и валюты, даты, количество полного списка и итоги. `monthlyEquivalent` и `actualCharges` сохраняются независимыми; количество подписок сервером не возвращается и клиентом не выдумывается. Календарный расчёт, периодичность и исторические списания выполняет backend. Прошедшие даты не переносятся клиентом автоматически.

Сравнение с прошлым месяцем остаётся «нет данных»: endpoint не возвращает дельты. График использует округлённые целые доли для легенды и согласованные суммы сервера.

## Проверка

- 82 unit/SSR теста и production build с typecheck проходят.
- Реальные API-проверки на отдельном тестовом аккаунте: пустая сводка, пять RUB-платежей (1500 ₽) и один USD-платёж (10 USD), история категорий, отсутствие смешения валют, полный список. Сверен Swagger.
- Одинаковые результаты получены напрямую на 8080, через Vite proxy на 3001 и nginx proxy на 3000. Одноразовые подписки последнего набора удалены.
- Backend и frontend собраны через Docker Compose; БД использует существующий volume и локальный порт 5433, поскольку 5432 занят локальным PostgreSQL. `.env` не менялся.
- Браузерная проверка реального тестового аккаунта завершена: вход, карточки (800 ₽ месячного эквивалента и 1900 ₽ календарных списаний), четыре ближайших платежа и полный список из пяти RUB-платежей, отдельные USD-данные, оба попапа, история категорий, поиск с фильтром периода, пустой результат, сброс, настройки, выход и защита маршрута. На ширине 320 px проверены Dashboard и попап категорий, на 375 px — Dashboard и настройки; горизонтального переполнения страницы не обнаружено. Физические телефоны, все браузеры и ошибка сети в интерфейсе в этой проверке не проверялись.

Локальный запуск: `docker compose up -d --build` из корня с заполненным локальным `.env`. Если 5432 занят, перед запуском в PowerShell установить `$env:POSTGRES_PORT = '5433'`. Frontend: http://localhost:3000; Swagger: http://localhost:8080/swagger-ui/index.html. Для разработки: из frontend `npm.cmd run dev -- --host 127.0.0.1 --port 3001`.

## Результаты системной проверки и открытые вопросы

- Backend: 60 тестов `mvn verify` прошли в отдельном Docker-контейнере с изолированными базами Testcontainers.
- Дополнительная проверка реального API: 41 успешная проверка и два обнаруженных случая некорректного ответа на неверные параметры: `GET /api/dashboard/upcoming?limit=0` и `GET /api/dashboard/categories?threshold=101` возвращают 500 вместо ожидаемого 400. Обычные frontend-запросы эти неверные параметры не отправляют; исправление относится к backend.
- Дневной период означает повторение каждые сутки. При цене 199 USD и периоде 1 день месячный эквивалент равен 5970 USD. Серверный календарный расчёт восстанавливает расписание за весь выбранный месяц, включая дни до создания подписки. Ограничение датой начала действия не определено в описании: правило следует согласовать с аналитиками, не подменять расчётом на frontend.
- Сравнение с прошлым месяцем и автоматическое перемещение прошедшей даты не реализованы этой интеграцией. Новые статусы и подтверждение оплаты относятся к отдельному согласованному этапу.
- Одноразовые подписки последней системной проверки удалены; личные данные и рабочая база не сбрасывались. Проверка не означает прохождение независимого код-ревью или CI текущей ветки.
