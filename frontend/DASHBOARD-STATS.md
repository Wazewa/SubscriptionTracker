# Dashboard: верхние карточки — задача №70

## Источник требований

«Прототипы и описание страниц», версия 9, раздел «Экран Дашборд»:
https://ssau.saas.sferaplatform.ru/knowledge/pages?id=478

Реализуются две карточки из опубликованного изображения: зелёная «Подписки обходятся в месяц» и белая «Реально спишется в [месяце]».
Первая обозначает месячный эквивалент стоимости активных подписок, вторая — календарную сумму ожидаемых списаний за указанный месяц. Вторая не подтверждает фактическую оплату.
Сравнение с прошлым месяцем не выдумывается: история пока не подключена. В описании аналитиков эта аналитика отдельно отмечена как будущая доработка.

## Реализация

- `src/components/DashboardStatsCards.tsx`: две компактные карточки нового макета, крупные суммы, подпись сравнения и зелёная/розовая плашки «нет данных». Расчётные пояснения и период сохранены для вспомогательных технологий, но не занимают место в карточках. Есть skeleton и безопасная ошибка с повтором.
- `src/dashboard/statsModel.ts`: внутренняя модель представления, проверка месяца/денег/валюты, отмена получения данных. Это **не контракт API**.
- `src/dashboard/useDashboardStats.ts`: состояния loading/unavailable/error/ready, повтор, защита от устаревших ответов при уходе/смене сессии. При 401 будущего API-адаптера завершается сессия.
- `src/dashboard/statsDemo.ts`: только синтетические данные для DEV-демосессии. Они не подставляются настоящему пользователю и не заменяют ошибку запроса.

Деньги во внутренней модели — целые копейки RUB. Разные валюты не суммируются и не конвертируются автоматически. Нулевые суммы отображаются как нули, недоступные — как прочерки, а не нули. Подпись месяца в готовом состоянии берётся из данных, а не из текущей даты компьютера.

Верхняя панель также приведена к новому прототипу: увеличен заголовок Dashboard, подзаголовок «Ваши подписки в одном месте», белая плашка «месяц» и розовая кнопка добавления. «месяц» — статическая подпись доступного периода, не работающий переключатель истории. Панель демо-сценариев находится в раскрываемом блоке внизу; у верхних карточек остаётся явная отметка тестовых данных. Пустые копейки в суммах скрыты, ненулевые сохраняются.

## Ограничение интеграции

На момент выполнения backend №69 и согласованный контракт статистики отсутствуют; пользователь это подтвердила. Поэтому в обычной сессии выводятся две карточки с прочерками и сообщением «API статистики ещё не подключён». Нет запросов к выдуманным endpoint.

`useDashboardStats` допускает будущий `DashboardStatsLoader`, который должен преобразовать согласованный DTO сервера во внутреннюю модель. Продуктовый адаптер сейчас **не задан**. После получения Swagger нужно подключить реальные запросы через общий API-клиент (токен, таймаут/отмена, безопасные ошибки), согласовать валюты, CUSTOM-период, календарь и сравнение с предыдущим месяцем. Самостоятельный пересчёт клиентом вместо отсутствующей серверной статистики в эту задачу не добавлен.

По отдельной просьбе выполнена frontend-часть №71: SVG-кольцо с уменьшенным белым центром, зелёно-серая палитра, суммы при наведении и выбор категории мышью/клавиатурой. Интеграция API ещё не выполнена. Детали — [DASHBOARD-CHART.md](DASHBOARD-CHART.md). Розовый фон кнопок Dashboard и плашки сравнения осветлён по примеру пользователя. Таблица списаний, попапы и разбивка по периодичности этой работой не реализуются заново; это отдельные задачи. В DEV сохранена предыдущая демонстрация остальных блоков.

## Проверка

Из `frontend/`: `npm.cmd test`, `npm.cmd run build` (включает typecheck).

В DEV: `/login` → «Открыть демо меню» → Dashboard → раскрыть «Состояния демонстрации» внизу. «Есть данные» показывает две разные тестовые суммы, «Нет подписок» — два нуля, «Загрузка» — два skeleton, «Ошибка» — прочерки и кнопку «Повторить загрузку сумм». Повтор из демонстрации ошибки возвращает данные. Проверить также узкий экран и длинные суммы.

Без демо (в том числе в Docker production) тестовые суммы недоступны. Приёмка реального API, независимое ревью, CI и закрытие задачи пока не выполнены; зелёные локальные тесты не заменяют эти пункты DoD.

## Результаты локальной проверки

- 64 теста пройдены, включая 13 тестов модели карточек, 6 серверных render-тестов карточек и 7 проверок модели/представления диаграммы. Render-тесты проверяют отсутствие ложных нулей/сумм при отсутствии API, loading/error, доступные подписи и кнопку повтора; подключения к настоящему backend они не доказывают.
- Typecheck и production build успешны.
- В DEV-браузере проверены разные суммы, пустой список с двумя нулями, два skeleton, ошибка без старых сумм и успешный повтор после ошибки.
- На 320/375/768/1280 px нет горизонтального переполнения документа или карточек; на узких экранах карточки расположены друг под другом. Это Chromium viewport, не физические устройства.
- `docker compose up -d --build frontend` завершён; контейнер healthy, `/health` и SPA-маршрут `/dashboard` отвечают HTTP 200. Без входа production перенаправляет на `/login`, демо-входа нет. Полный стек и вход в production в этой задаче не проверялись.
- При сборке обнаружено предупреждение аудита зависимостей. Дополнительный `npm audit` подтвердил одну high-уязвимость уже установленного Vite 7.3.6. Версии пакетов и lockfile этой задачей не менялись; обновление требуется отдельно.
