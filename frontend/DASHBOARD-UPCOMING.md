# Ближайшие списания — frontend задачи №72

## Требования и изменения описания

Источник: экспорт «Прототипы и описание страниц-11.docx» со страницы знаний https://ssau.saas.sferaplatform.ru/knowledge/pages?id=478, раздел «Дашборд» и приложенный макет.

Обновлённое описание задаёт **топ-4**, хотя в прежнем описании задачи был топ-5. Слева в строке размещаются иконка, название и категория; справа — сумма и дата. «Все» открывает попап всех ближайших списаний, а переход на страницу подписок выполняется из попапа кнопкой «Все подписки».

## Реализация

- `UpcomingPayments.tsx`: отдельный блок и семантическая таблица, текстовые заголовки для вспомогательных технологий, четыре skeleton-строки, loading/ready/empty/error/unavailable. Числовые суммы не подставляются при отсутствии данных, ошибка не показывает внутренние серверные сообщения.
- `PaymentRows`: перенос длинных названий и сумм; локальная иконка с инициалами сервиса без внешних запросов. Это запасная иконка, не фирменные логотипы с макета — готового справочника логотипов в проекте нет.
- Внутренняя модель дополнена необязательным `categoryName`. Сортировка по календарной дате от ближайшей с устойчивым порядком по id при равенстве; включено сегодня, прошедшие даты исключены, исходный массив не меняется. Лимит четыре вынесен в `UPCOMING_PAYMENTS_LIMIT`.
- Сумма — стоимость конкретного платежа в копейках RUB, а не месячный эквивалент. Даты отображаются без UTC-сдвига; суммы и даты не пересчитываются по периодичности на клиенте.
- В Dashboard подключены состояния нового блока, устранён дублирующий старый skeleton списка. Повтор после демонстрационной ошибки возвращает данные.

## Зависимости и ограничения

В свежем master опубликован backend API Dashboard (задача №69). Подключение frontend к этому контракту не входит в эти изменения. В обычной сессии блок явно сообщает, что API не подключён; демоданные доступны только в DEV-демосессии.

Попап №73 Полины из ветки `feature/dashboard-modals-73-74` подключён к «Все». На Dashboard показаны четыре ближайших платежа, в попапе — полный список будущих платежей, сгруппированный по месяцам, с итогом. Прошедшие даты исключаются в обоих местах. Из попапа «Все подписки» ведёт на /subscriptions. Топ-4 согласован с пользователем по обновлённому описанию.

Попап №74 открывается кнопкой «Подробнее» и нажатием на диаграмму/категорию. Оба окна используют нативный dialog: закрытие крестиком, Escape и фоном, начальный фокус на заголовке, возврат фокуса и блокировка прокрутки фона. Независимое ревью, CI и ручная браузерная проверка объединённой версии ещё предстоят. API — отдельный этап интеграции; он не указан в AC задачи №72.

Прочитаны также новые требования к «Другому» в диаграмме, попапам, статусам подписок и уведомлениям. Они не включены в задачу №72. Порог группировки малых категорий указан неоднозначно (5% либо 1%) и требует решения аналитиков. Календарный расчёт и исключение неактивных подписок должны быть согласованы с backend при подключении API.

## Проверки и просмотр

- 76/76 локальных тестов проходят, включая полный список из шести будущих платежей, исключение прошедших дат, неизменность массива, итог, категории и пустые состояния.
- Typecheck и production build успешны.
- Для предыдущей версии №72 проверен Docker frontend. Для объединённой версии Docker-сборка не проверена: Docker Engine был выключен.
- Интерактивная браузерная проверка объединённой версии не завершена. SSR-тесты не подтверждают работу фокуса, прокрутки и адаптивности в браузере.

Просмотр: `npm.cmd run dev -- --host 127.0.0.1 --port 3001` из frontend, затем /login → «Открыть демо меню» → /dashboard. Внизу раскрыть «Состояния демонстрации» и проверить все четыре состояния. На узком экране вручную проверить отсутствие горизонтальной прокрутки и перенос длинных названий. Без демосессии реальные платежи не отображаются до подключения API.
