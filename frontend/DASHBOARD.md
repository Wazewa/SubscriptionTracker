# Dashboard — задача №11

## Текущие доработки №70 и №71

Верхний блок заменён двумя карточками из актуального прототипа: месячный эквивалент и календарная сумма списаний. Добавлены собственные skeleton/ошибка/повтор и состояние без API. Детали и ограничения — [DASHBOARD-STATS.md](DASHBOARD-STATS.md). Кольцевая диаграмма обновлена: уменьшенный центр, сумма и доля при наведении, управление через легенду и клавиатуру — [DASHBOARD-CHART.md](DASHBOARD-CHART.md). Таблица списаний ниже — заготовка предыдущего спринта.

Статус: frontend-часть подготовлена. Интеграция с backend не выполнена, так как API пока отсутствует. Задачу не закрывать до подключения и проверки реальных данных.

## Реализовано

- Сумма за выбранный сервером месяц (в демо — текущий месяц).
- Круговая диаграмма, легенда с суммами и долями категорий. Округлённые доли суммируются до 100%.
- До пяти ближайших списаний: по дате, включая сегодня, без прошедших дат.
- Skeleton, пустое состояние, ошибка и повторная загрузка.
- Ссылка «Все» в /subscriptions и кнопка «Добавить подписку» в /subscriptions/new.
- Форма /subscriptions/new реализована позднее в задачах подписок; не относится к объёму этой заготовки Dashboard.
- Адаптивная компоновка, текстовая легенда диаграммы для доступности, отключение анимации при reduced motion.

## Проверка

Из frontend: `npm run test`, `npm run build`, `npm run dev`.

В режиме разработки: открыть /login → «Открыть демо меню» → /dashboard. Баннер явно обозначает тестовые данные. Кнопки «Есть данные», «Нет подписок», «Загрузка», «Ошибка» переключают состояния. В обычном демо загрузка длится 650 мс. Из шести тестовых подписок в списке показываются пять ближайших.

В production нет демо-кнопок и данных. При реальной сессии верхние карточки отображают прочерки и сообщение об отсутствии интеграции. Никакие придуманные эндпоинты не вызываются.

## Подключение backend после появления API

1. Согласовать эндпоинт и JSON, определение суммы за месяц (фактические списания или плановые расходы), учёт годовых подписок, валют и часового пояса.
2. Написать адаптер к внутренней модели DashboardData из src/dashboard/model.ts. Это модель frontend, не утверждённый API-контракт. Сейчас поддерживается RUB; деньги хранятся в копейках, без вычислений с дробными рублями.
3. Заменить ветку без isDemo в useDashboard.ts на реальный запрос с токеном, отменой при размонтировании, таймаутом, обработкой 401/403 и повтором. Демо-ветка не должна использоваться как запасные данные при ошибке API.
4. Проверить ответы сервера, общую сумму и категории, нулевые расходы, отсутствие подписок, даты ближайших платежей и ограничение до пяти записей. Не суммировать разные валюты без согласованной конвертации.
5. Проверить настоящий вход, обновление страницы, интеграцию формы добавления, пройти ревью и только затем закрыть задачу.

Суммы, даты и категории демо используются исключительно для проверки интерфейса. Корректность данных backend пока не подтверждена.
