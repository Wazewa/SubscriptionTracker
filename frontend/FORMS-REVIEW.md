# Ревью и интеграция форм подписок

Источник: коммит Полины `09a0cc9` из `feature/subscription-forms`.
Перенесён только frontend-коммит с сохранением авторства, без сопутствующих backend-коммитов.
Конфликт общей оболочки разрешён с сохранением LogoutButton из задачи №26 и заголовков новых форм.

## Найдено и исправлено

1. Кнопки сохранения вызывали пустые обработчики. Теперь форма явно обозначена как предпросмотр, а отправка корректной формы сообщает, что данные НЕ сохранены из-за отсутствия API. Ложного сообщения об успехе нет.
2. Подтверждение удаления только закрывало окно, несмотря на обещание выполнить действие. Теперь ограничение показано до подтверждения и после нажатия «Удалить»; строка не удаляется и окно не имитирует успех.
3. Выпадающее меню последней строки обрезалось контейнером таблицы. Меню теперь раскрывается в потоке строки, доступно внутри горизонтальной прокрутки, закрывается по Escape и при уходе фокуса.
4. Удаление было обычным блоком с aria-modal без управления фокусом. Использован отдельный DeleteConfirmModal на нативном dialog: фокус внутри окна, Escape, отмена, возврат к кнопке действий.
5. Стоимость принимала экспоненциальную и шестнадцатеричную запись, а также доли копейки. Теперь допускается десятичная сумма не более двух знаков после разделителя, с проверкой безопасного диапазона.
6. Уточнена подпись «Стоимость за месяц»: форма использует monthlyPriceMinor, а не стоимость полного годового периода. Семантику платежа и округление нужно подтвердить при интеграции API.
7. При редактировании категория вне статического списка теперь остаётся доступной. Период проверяется явно. Добавлены тесты модели формы и валидации.

## Что ещё не реализовано — не ошибка передачи веток

- Создание, обновление и удаление на сервере; пока нет соответствующего API.
- Словарь категорий с backend (сейчас локальный список + текущая категория).
- Загрузка подписки по id: прямой URL редактирования без navigation state показывает понятное сообщение и переход к списку. Требует будущего API.
- Уведомления об успешных изменениях и обновление списка после реальных запросов.

Новые формы не создают и не сохраняют даже демо-записи. Они предназначены для проверки UI до подключения API.
Исходная ветка Полины не менялась. master не менялся. Для полной приёмки нужен backend и независимая проверка коллегой.
