# Кнопка «Выход» — №26

Кнопка уже существовала в общей оболочке. В задаче №26 она выделена в компонент `LogoutButton`, а очистка сессии — в тестируемый модуль `auth/session.ts`.

## Поведение

- «Выйти» доступна в Sidebar всех внутренних страниц, с иконкой и клавиатурным фокусом.
- Удаляются только `subscription-tracker.token` и `subscription-tracker.demo` из sessionStorage.
- Обе попытки удаления выполняются независимо. Недоступное хранилище не мешает очистить текущего пользователя из памяти.
- Сбрасываются пользователь, ошибка авторизации и состояние загрузки.
- Счётчик поколения сессии не позволяет незавершённому входу или проверке профиля восстановить пользователя после выхода.
- Переход на `/login` выполняется с `replace`. Защищённые маршруты остаются недоступны после выхода, включая переход «Назад», обновление страницы и прямой URL.
- Повторный выход безопасен. Сторонние данные хранилища не очищаются.

Это выход из локальной сессии текущей вкладки, НЕ отзыв JWT на сервере и НЕ выход со всех устройств. API отзыва токена пока не подключён.
Если браузер запретил удаление данных, frontend не может гарантировать физическое удаление токена из хранилища; текущая сессия в памяти всё равно завершается.

## Проверка

1. В режиме разработки открыть `/login`, нажать «Открыть демо меню».
2. Перейти на подписки или настройки, нажать «Выйти» — открывается форма входа, меню скрыто.
3. Нажать «Назад», обновить страницу и открыть `/dashboard`, `/subscriptions`, `/subscriptions/new`, `/settings` напрямую — остаётся форма входа.
4. Войти в демо повторно — меню снова доступно.
5. Для обычной сессии повторить сценарий после реального входа с backend. Не передавать JWT и пароли в отчёты/скриншоты.

`npm test` включает тесты очистки реального и демо-ключей, сохранения сторонних данных, повторного выхода и ошибок хранилища.
Независимое код-ревью и закрытие задачи в трекере выполняются отдельно после приёмки.
