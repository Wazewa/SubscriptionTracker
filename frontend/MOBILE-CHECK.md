# Toast-уведомления и адаптивность frontend

## Объём

Доработка задач №39, №50, №51: toast создания, обновления, удаления и ошибки удаления. Проверка текущих страниц без расширения API и без подключения Dashboard (следующий спринт).

## Уведомления

- Общий ToastProvider сохраняет уведомления при переходах между внутренними страницами и очищается при выходе из защищённой оболочки.
- «Подписка создана», «Подписка обновлена», «Подписка удалена» появляются только после успешного ответа API. Inline-сообщение в navigation state заменено toast, поэтому оно не воспроизводится повторно после обновления страницы/возврата назад.
- Ошибки сохранения и удаления показываются безопасным текстом. В модальном окне удаления есть отдельный toast-контейнер внутри dialog: уведомление не скрывается под native modal/top layer и доступно вспомогательным технологиям.
- Успешные уведомления скрываются через 8 секунд; при наведении или клавиатурном фокусе таймер приостанавливается. Ошибки остаются до ручного закрытия. Есть доступная кнопка закрытия размером 44×44 px.
- Не более трёх уведомлений одновременно; повтор одного сообщения в той же области заменяет предыдущую копию. Уведомления модалки удаляются при её закрытии, не затрагивая остальные.
- Успех использует role=status, ошибка role=alert. Toast не перехватывает фокус. Дополнительная библиотека не устанавливалась.

## Исправлено при мобильной проверке

- Переполнение заголовка и кнопки регистрации на 320 px; уменьшены мобильные отступы и подобран размер шрифта.
- Заголовки внутренних страниц и иконки корректно переносятся; на планшете длинное слово «Редактирование» больше не разбивается последней буквой.
- Исправлен containing block у таблицы: скрытая подпись действий больше не создаёт горизонтальную прокрутку всего документа. Сама таблица сохраняет собственную горизонтальную прокрутку.
- Раскрываемое меню действий автоматически прокручивается в видимую область, включая последнюю строку. Кнопки действий увеличены до 44 px.
- Окно удаления ограничено высотой viewport, поддерживает прокрутку и длинные названия без пробелов.
- Окно согласия открывается с начала текста, фокус попадает на заголовок; поддержаны переносы длинного текста и Escape. Юридический текст не менялся.

## Проверки в браузере

| Ширина viewport | Вход / регистрация | Список / создание / редактирование / настройки |
| --- | --- | --- |
| 320 px | Без горизонтального переполнения | Без горизонтального переполнения документа |
| 375 px | Проверено | Проверено |
| 390 px | Проверено | Проверено |
| 768 px | Проверено | Проверено |
| 1280 px | Проверено | Проверено |

Размеры проверялись по фактическим clientWidth/scrollWidth документа; вертикальная полоса прокрутки может уменьшать рабочую ширину на 15 px. Дополнительно проверен короткий viewport 844×390, доступность меню и кнопок окна удаления.

На отдельном локальном тестовом аккаунте через интерфейс проверены создание, изменение и удаление новой одноразовой подписки и соответствующие toast. Для ошибки использована вторая одноразовая запись: она была удалена другим запросом при открытой модалке; UI получил реальный 404, показал ошибку и не показал успех. Проверены закрытие уведомления, Escape и возврат из модального окна.
Обе созданные в этой проверке записи удалены; существующие подписки, пользовательские пароли и данные не менялись. Демо не имитирует серверный успех.

`npm test` покрывает очередь уведомлений, дедупликацию и очистку по области; также сохраняются тесты API, форм, авторизации и выхода. Перед передачей нужно выполнить `npm run build` (включает typecheck).

Это проверка responsive-layout в Chromium, а не на физических телефонах: Safari/iOS, экранная клавиатура, системные масштабы шрифта и реальные touch-жесты отдельно не проверялись.
Независимое ревью этой доработки ещё требуется. Условия серверной фильтрации и месячного пересчёта цены не менялись и требуют согласования с командой.
