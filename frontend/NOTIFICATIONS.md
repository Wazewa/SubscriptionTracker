# №93 — уведомления и подключение API

## Локальный запуск

Разработка ведётся в `feature/tpivt9-26-93-notifications`. Изменения не опубликованы.
Контейнеры исходного проекта используют прежнюю базу `tp_ivt_team9_2026_postgres_data`.
Приложение: http://localhost:3000. Swagger: http://localhost:8080/swagger-ui.html.
Для просмотра демо: в `frontend` выполнить `npm ci`, затем
`node node_modules/vite/bin/vite.js --host 127.0.0.1 --port 3006`;
на http://127.0.0.1:3006 выбрать «Открыть демо меню» и колокольчик.

## Реальные данные

- GET `/api/notifications`: загрузка при входе, открытии панели и повторе.
- Запросы идут на тот же origin через nginx, с Bearer-токеном текущей сессии.
- При 401 выполняется выход; отменённые и устаревшие ответы не обновляют экран.
- Проверяются ID, даты и формат данных. Ошибка сервера не заменяется демо-данными.
- Поля `type` в текущем NotificationResponse нет. Карточка показывает реальный
  текст с общим заголовком «Уведомление». Если сервер начнёт возвращать один из
  пяти известных типов, оформление типа будет применено без угадывания по тексту.
- Метода «прочитано» нет: кнопка «Прочитать» сохраняет отметку в localStorage
  отдельно для пользователя и демо. Отправка в Telegram не означает прочтение.
- Неизвестный тип не попадает в фильтр «Платежи» без явных данных о типе.

## Подтверждение списания

- GET `/api/subscriptions/me` загружает собственные подписки при открытии панели.
- В «Требуют подтверждения» попадают ACTIVE с датой не позже сегодня и UNPAID;
  будущие ACTIVE, PAUSED и CANCELLED не показываются как ожидающие подтверждения.
- Кнопка «Подтвердить списание» сначала спрашивает, состоялась ли оплата.
- Только по «Да, оплата прошла» отправляется POST
  `/api/subscriptions/{id}/confirm-payment`, без тела запроса.
- Проверяется, что ответ относится к той же подписке, статус ACTIVE, дата в будущем.
- После успеха обновляются данные дашборда и списка подписок без перезагрузки.
- Повторный POST блокируется на время запроса; автоматических повторов нет.
  При неопределённом результате выполняется сверка через GET.
- Это запись факта оплаты в трекере, а не платёж банку. Новая дата определяется
  существующим бэкендом от дня подтверждения. Чтение уведомления её не меняет.

## Макет

Белая панель, розовый активный фильтр, зелёные непрочитанные карточки;
«Все», «Непрочитанные» со счётчиком и «Платежи», сортировка и группировка по дням.
Ширины 320 / 390 / 768 / 1440px, прокрутка внутри панели, Escape и возврат фокуса.
Демо содержит все пять типов и переключатели данных, пустого списка, загрузки, ошибки.
Удаление уведомлений и отправка в Telegram не добавлены: они не входят в AC №93.
Backend-код и контракт API не изменены.
