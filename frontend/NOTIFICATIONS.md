# №93 — уведомления и подключение API

## Локальный запуск

Разработка ведётся в `feature/tpivt9-26-93-notifications`. Текущая реализация передаётся на ревью; ограничения перечислены ниже.
Контейнеры исходного проекта используют прежнюю базу `tp_ivt_team9_2026_postgres_data`.
Приложение: http://localhost:3000. Swagger: http://localhost:8080/swagger-ui.html.
Для просмотра демо: в `frontend` выполнить `npm ci`, затем
`node node_modules/vite/bin/vite.js --host 127.0.0.1 --port 3006`;
на http://127.0.0.1:3006 выбрать «Открыть демо меню» и колокольчик.

## Реальные данные

- GET `/api/notifications`: загрузка при входе, открытии панели и повторе.
- Запросы идут на тот же origin через nginx, с Bearer-токеном текущей сессии.
- При 401 выполняется выход; отменённые и устаревшие ответы не обновляют экран.
- Проверяются ID, даты и формат данных. Ошибка сервера не заменяется демо-данными.
- Поля `type` в текущем NotificationResponse нет. Карточка показывает реальный
  текст с общим заголовком «Уведомление». Если сервер начнёт возвращать один из
  известных типов, оформление типа будет применено без угадывания по тексту.
- Метода «прочитано» нет: кнопка «Прочитать» и открытие карточки сохраняют отметку в localStorage
  отдельно для пользователя и демо. Отправка в Telegram не означает прочтение.
- Неизвестный тип не попадает в фильтр «Платежи» без явных данных о типе.

## Подтверждение списания

- GET `/api/subscriptions/me` загружает собственные подписки при открытии панели.
- В «Требуют подтверждения» попадают ACTIVE с датой не позже сегодня и UNPAID;
  будущие ACTIVE, PAUSED и CANCELLED не показываются как ожидающие подтверждения.
- Кнопка «Да» открывает отдельное окно подтверждения состоявшейся оплаты.
- «Нет» открывает выбор редактирования или удаления подписки. Переходы используют
  существующие формы; удаление требует отдельного подтверждения.
- Для известных типов PAYMENT_REMINDER / PAYMENT_PROBLEM действия доступны
  внутри карточки связанной подписки. Без типа события используется отдельный блок.
- Только по «Да, оплата прошла» отправляется POST
  `/api/subscriptions/{id}/confirm-payment`, без тела запроса.
- Проверяется, что ответ относится к той же подписке, статус ACTIVE, дата в будущем.
- После успеха обновляются данные дашборда и списка подписок без перезагрузки.
- Повторный POST блокируется на время запроса; автоматических повторов нет.
  При неопределённом результате выполняется сверка через GET.
- Это запись факта оплаты в трекере, а не платёж банку. Новая дата определяется
  существующим бэкендом от дня подтверждения. Чтение уведомления её не меняет.

## Макет

Белая панель, розовый активный фильтр, зелёные непрочитанные карточки;
«Все», «Непрочитанные» со счётчиком и «Платежи», сортировка и группировка по дням.
Ширины 320 / 390 / 768 / 1440px, прокрутка внутри панели, Escape и возврат фокуса.
Демо показывает в том числе «Скоро списание», «Списание успешно» и «Проблема с подпиской».
Доступны переключатели данных, пустого списка, загрузки и ошибки. В демо подтверждение оплаты отключено.
Меню уведомления позволяет отметить его прочитанным и скрыть только в текущем браузере,
с возможностью отмены. Состояние хранится отдельно для каждого пользователя и демо.
В карточке можно просмотреть загруженную связанную подписку и перейти к редактированию.
На колокольчике отображается число непрочитанных.
Серверные удаление, архивирование и прочтение не подключены.
После подтверждения оплаты известные напоминания и проблемы этой подписки скрываются локально.
Отправка сообщений в Telegram через интерфейс не добавлена.
Окно выбора статуса подготовлено, но сохранение отключено до появления API смены статуса.
UNPAID поддерживается в основном списке; ежедневный период использует существующий CUSTOM / 1 день.
В ближайших списаниях можно фильтровать уже загруженные платежи по доступным месяцам.
Backend-код и контракт API не изменены.

## Проверки

`npm test` (130 тестов), `npm run build`, `git diff --check`.
API-тесты проверяют реальные пути и заголовки, DTO, фильтрацию платежей,
успех подтверждения, 400/401/403, отмену, неопределённый результат и отсутствие
автоматического повторного POST. Тесты не изменяют подписки пользователя.

Последние доработки проверены в браузере на ширинах 320 и 375 пикселей.
Docker Compose после последних доработок повторно не проверялся.
Полный DoD задачи не закрыт: требуется согласование недостающего API.
