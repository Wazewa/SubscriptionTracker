# Меню и маршрутизация (задача №10)

## Проверка локально

В папке frontend выполните `npm ci`, затем `npm run dev`. Если Docker-фронтенд занимает порт 3000, сначала остановите только его: `docker compose stop frontend` из корня репозитория.

1. Откройте http://localhost:3000/settings без сессии: приложение должно перевести на /login.
2. Перейдите по ссылке регистрации: должен открыться /register. Вернитесь на /login.
3. Нажмите «Открыть демо меню». Эта кнопка существует только в режиме разработки и не отправляет данные на сервер.
4. Переключайтесь между «Дашборд», «Подписки», «Настройки»: адрес и заголовок меняются, активен ровно один пункт меню.
5. Проверьте переход в настройки через иконку аккаунта, обновление страницы и кнопки браузера Назад/Вперёд.
6. Нажмите «Выйти»: откроется /login; прямые адреса /dashboard, /subscriptions, /settings снова закрыты.
7. Уменьшите ширину окна: меню переносится над содержимым, ссылки остаются доступными.

Проверка TypeScript и production-сборки: `npm run build`.
Проверка сборки: `npm run preview -- --port 3001`. Демо-вход в ней отсутствует; без подтверждённой сервером сессии закрытые страницы недоступны. Nginx уже настроен на отдачу index.html для прямого открытия маршрутов.

## Что реализовано

- React Router: /login, /register, /dashboard, /subscriptions, /settings.
- Общая оболочка закрытых страниц, меню с существующими иконками, подсветкой через NavLink и aria-current.
- Защита маршрутов, проверка сессии, выход и восстановление адреса после демо-входа.
- Дашборд и подписки пока являются явно обозначенными заглушками: данные, таблицы и CRUD относятся к следующим задачам.

## Зависимость от авторизации

Формы входа/регистрации из ветки feature/auth-settings пока не подключены к API. Эта задача не реализует регистрацию или выдачу JWT.

Для серверной сессии AuthProvider читает JWT из sessionStorage по ключу `subscription-tracker.token` и проверяет его запросом GET `${VITE_API_BASE_URL}/auth/me` с Authorization: Bearer. Ожидается успешный JSON-ответ с полем email (строка); контракт необходимо согласовать с backend-разработчиком. При ошибке, неверном ответе или таймауте доступ закрывается. Наличие токена само по себе не открывает страницы.

По умолчанию базовый адрес /api. До интеграции нужно настроить проксирование этого адреса либо задать VITE_API_BASE_URL с адресом API и настроить CORS на сервере. После подключения формы логина она должна сохранить выданный токен и инициировать повторную проверку сессии (например, перезагрузкой страницы на нужном маршруте). Сервер обязан независимо проверять авторизацию каждого защищённого запроса; защита React-маршрутов не заменяет её.

Демо-сессия хранится только в текущей вкладке. Она исключена из production-сборки и не является настоящей авторизацией. Настройки показывают email сессии; изменение пароля отключено до реализации API.

Код-ревью и закрытие задачи в трекере выполняются после проверки и принятия изменений командой.
