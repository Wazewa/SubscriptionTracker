# Регистрация: согласие и подтверждение почты

Локальная frontend-доработка; API регистрации пока отсутствует.

- Перед кнопкой есть изначально пустая галочка и ссылка-кнопка «Текст согласия».
- Без галочки отправка формы блокируется, отображается ошибка, фокус переходит на галочку.
- Окно согласия использует native dialog: блокирует взаимодействие с фоном, закрывается кнопкой и Escape, восстанавливает фокус.
- Проверяются обязательные поля, email, минимальная длина пароля 8 символов и совпадение паролей.
- Реальных запросов, сохранения персональных данных или отправки писем нет.
- Сообщение о подтверждении почты можно посмотреть отдельной кнопкой только в DEV. Предпросмотр явно обозначен; это не успешная регистрация. Возврат сбрасывает галочку.

## Что осталось

1. Ответственный за проект предоставляет утверждённый текст согласия и его версию. Их нужно поместить в src/registration/consentDocument.ts. Пустой документ не считается согласием: в production галочка отключена, пока нет текста и версии.
2. Backend согласует контракт регистрации, проверку и хранение согласия/версии, отправку письма и поведение входа до подтверждения.
3. После подключения API сообщение EmailConfirmationMessage с preview=false показывается только по подтверждённому успешному ответу сервера; ошибки API остаются на форме. Не отправлять пароли в URL, логи или хранилище браузера. Не объединять это согласие с рекламными рассылками.
4. Проверить реальную регистрацию и переход по ссылке из настоящего письма.

Для ручной проверки: /register → нажать регистрацию без галочки → открыть текст согласия → закрыть Escape → отметить галочку → проверить поля → открыть предпросмотр сообщения о почте. Это макет для согласования, не готовая юридическая или серверная реализация.
