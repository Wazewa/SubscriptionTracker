# Подписки: интерфейс и API

## Реализовано

- `/subscriptions`: существующие Sidebar/Header и защита маршрута, таблица, поиск, фильтры категории и периода, сброс.
- Skeleton, пустой список, пустой результат фильтров, ошибка и повторная загрузка.
- Категории для таблицы, фильтров и форм загружаются из полного справочника backend, значения select — ID, а не названия.
- Создание, редактирование и удаление выполняются на сервере. После успешного ответа список загружается заново; при ошибке успех не имитируется.
- Прямой URL `/subscriptions/:id/edit` и перезагрузка работают: запись ищется в полном списке текущего пользователя. GET отдельной подписки в контракте пока нет.
- Настоящий аккаунт не получает демо-данные при ошибке. DEV-демо отдельно обозначено, не отправляет операции изменения и не сохраняет демо-записи.

## Контракт, сверенный со Swagger на localhost:8080

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| GET | `/api/categories` | `[{categoryId, name, description}]` |
| GET | `/api/subscriptions/me` | Полный массив своих подписок |
| POST | `/api/subscriptions` | Создание, 201 + SubscriptionResponse |
| PUT | `/api/subscriptions/{id}` | Изменение, 200 + SubscriptionResponse |
| DELETE | `/api/subscriptions/{id}` | Удаление, 204 без тела |

Все запросы передают Bearer-токен существующей сессии; базовый адрес — `VITE_API_BASE_URL` или `/api`.
Старый флаг `VITE_SUBSCRIPTIONS_API_ENABLED` больше не используется: контракт реализован, реальные аккаунты обращаются к API по умолчанию.
Vite и nginx сохраняют префикс `/api` и направляют запросы к backend:8080. Секреты в frontend не нужны.

Тело создания/изменения:

```json
{
  "name": "Сервис",
  "amount": 299.99,
  "currency": "RUB",
  "nextPaymentDate": "2026-11-20",
  "period": "MONTHLY",
  "periodDays": null,
  "categoryId": 1
}
```

- Валюты: RUB, USD, EUR, CNY. Периоды: WEEKLY, MONTHLY, YEARLY, CUSTOM.
- Для CUSTOM передаётся положительное целое periodDays; для остальных периодов — null.
- Ответ содержит числовые id/categoryId, amount, currency, nextPaymentDate, period, periodDays, status (ACTIVE/PAUSED/CANCELLED), createdAt/updatedAt. Frontend проверяет формат и преобразует сумму в целые минимальные единицы валюты.
- `amount` — полная стоимость периода, не месячный эквивалент. Редактирование сохраняет именно её. Валюты не конвертируются. В «Цена/мес» значение есть только для MONTHLY; для остальных периодов указана полная стоимость периода. Формула месячного пересчёта требует отдельного согласования.
- Название — до 100 символов; сумма положительная, до двух десятичных знаков и в пределах NUMERIC(12,2); дата существует и не раньше текущего локального дня.
- Пустой справочник блокирует сохранение и показывает объяснение. Неизвестная категория не подменяется другой.

## Фильтры и ошибки

Swagger не содержит query-параметров и пагинации для списка. Поэтому фильтры применяются локально к **полному** ответу GET /me, без вымышленных параметров search/category/period.
При появлении серверной фильтрации/пагинации нужно обновить контракт и эту логику одновременно.

Таймаут — 10 секунд; уход со страницы отменяет запросы. Устаревшие ответы не обновляют экран; повторная отправка операции блокируется.
401 завершает локальную сессию, 400/403/404/409 и другие ошибки имеют безопасные сообщения без внутренних серверных подробностей.
При сетевом сбое операции изменения результат может быть неизвестен: пользователь получает совет сначала обновить список. Автоматического повтора POST/PUT/DELETE нет.
Окно удаления использует нативный dialog, Escape/отмену и возврат фокуса; подтверждение не доступно во время запроса и в демо.

## Проверки и ограничения

Toast создания/обновления/удаления и ошибки удаления реализованы; уведомления об успехе показываются только после ответа backend. При переходе к списку они не теряются и не повторяются из navigation state.
Адаптивность проверена на 320/375/390/768/1280 px, исправлены найденные переполнения и доступность меню. Подробности, сценарии и ограничения проверки на реальных устройствах — в [MOBILE-CHECK.md](MOBILE-CHECK.md).

`npm test` проверяет DTO, справочник, деньги, даты, фильтры, поля запросов, ошибки, отмену и таймауты. `npm run build` включает проверку типов.
На разрешённых отдельных локальных тестовых аккаунтах проверены реальные категории, GET/POST/PUT/DELETE. Через браузер проверены пустой список, ошибки формы, создание, комбинация фильтров/сброс, редактирование после перезагрузки, валюты/CUSTOM, отмена окна удаления и фокус.
Одна тестовая подписка из первоначальной проверки оставлена в отдельном UI-аккаунте для просмотра; чужие записи не менялись. Новые одноразовые записи проверки toast удалены. Проверка физических мобильных устройств ещё требуется.
Dashboard API этой работой не подключён. Независимый код-ревью и закрытие задач в трекере не выполнялись.
