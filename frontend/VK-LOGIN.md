# Вход через VK ID — задача №121

Кнопка «Войти через ВК» на `/login` запускает Authorization Code + PKCE.
Frontend генерирует случайные verifier/state, хранит их в sessionStorage текущей
вкладки и отправляет в VK только challenge S256 и state. Callback
`/auth/vk/callback` проверяет state, срок 10 минут, обязательные поля и повторное
использование, удаляет OAuth-параметры из адреса и передаёт backend:

`POST /api/auth/vk` → `{ code, codeVerifier, deviceId, state }` → `{ token }`.

После успешного `GET /api/auth/me` сохраняется JWT приложения и открывается
исходная защищённая страница либо `/dashboard`. Отмена/ошибки оставляют
возможность вернуться на обычный вход. Иконка профиля ведёт на `/settings`
(реализация и проверки из №129).

## Настройка реального приложения

Backend уже содержит VK OAuth client. Реальный Client ID отсутствует в
`.env.example`: его предоставляет ответственный за VK-приложение.

В корневом `.env` задать публичный `VK_CLIENT_ID` и зарегистрированный
`VK_REDIRECT_URI`, например `http://localhost:3000/auth/vk/callback`.
Compose передаёт те же значения backend и frontend при сборке. После изменения
настроек выполнить `docker compose up -d --build`. Секрет клиента не нужен и не
должен передаваться в VITE-переменных.

Для Vite вне Docker задать в `frontend/.env.local`:
`VITE_VK_CLIENT_ID` и `VITE_VK_REDIRECT_URI`. Redirect URI должен точно совпадать
с настройкой backend и VK ID, быть на том же origin и иметь путь
`/auth/vk/callback`. Для production нужен HTTPS, HTTP допускается для localhost.
Незаполненная конфигурация не заменяется фиктивным ID: кнопка сообщает, что вход
через ВК пока недоступен, обычный вход продолжает работать.

## Проверка

- `npm test`, `npm run build`.
- На `/login` есть отдельная кнопка ВК, не требующая заполнения email/пароля.
- В настроенной среде: вход/согласие VK → callback → защищённая страница;
  профиль → настройки; обновление страницы сохраняет подтверждённую сессию.
- Проверить отказ VK, просроченный/неверный state, повтор callback, ошибку API,
  возврат назад и повторный вход. Код и verifier не выводятся в сообщения.
- Проверка реального VK-аккаунта требует Client ID и зарегистрированного URI;
  автоматические тесты с тестовыми ответами не заменяют этот прогон.

Параметры сверены с официальным VK ID Web SDK:
https://github.com/VKCOM/vkid-web-sdk/blob/master/src/auth/auth.ts
